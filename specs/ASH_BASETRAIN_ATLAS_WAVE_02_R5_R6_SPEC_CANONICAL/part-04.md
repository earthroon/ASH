range byte-length mismatch count
```

Production-candidate policy requires:

```text
unmapped payload bytes = 0
```

unless a future explicit Safetensors extension record authorizes non-tensor payload bytes. No such extension is admitted in R5-R6.

Header padding before the first tensor does not become a tensor payload and must be handled according to the parsed Safetensors data-section geometry.

# 15. Config·header·payload convergence

R5-R6 emits one convergence receipt containing:

```text
config SHA-256
ModelSpec semantic digest
R5-R3 geometry digest
R5-R5 RoPE authority digest
index SHA-256 or explicit absence
ordered shard set digest
ordered shard CAS entries
ordered tensor inventory digest
canonical role inventory digest
parameter-count digest
payload-byte-count digest
```

Required equalities:

```text
config dimensions == ModelSpec dimensions
ModelSpec geometry == R5-R3 geometry authority
config RoPE fields == R5-R5 external RoPE authority
index key set == union of shard header key sets
canonical expected role set == resolved physical role set
header dtype/shape == canonical role dtype/shape policy
shard file digest == supplied expected CAS digest
```

No single source may silently overwrite another source.

A disagreement is a gate failure, not a precedence decision.

---

# 16. No synthetic tensor admission

R5-R6 must distinguish production-candidate sources from earlier deterministic fixtures.

The gate must reject when any of the following are true:

```text
checkpoint source path is under an R5 synthetic fixture directory
ModelSpec identity profile is SyntheticMhaFixture
ModelSpec identity profile is SyntheticGqaFixture
production_checkpoint_payload is false
checkpoint was generated by the R5 fixture writer
any tensor authority has synthetic = true
any missing role is filled with zeroes, random values or deterministic fixture values
any dtype/shape mismatch is repaired by reshaping or padding
```

No synthetic tensor count may be hidden behind tied-role aliasing.

Required result:

```text
synthetic_tensor_count = 0
```

---

# 17. Payload immutability

R5-R6 is read-only.

Forbidden operations:

```text
Safetensors rewrite
header rewrite
index rewrite
shard rename as authority mutation
tensor byte normalization
dtype conversion
padding insertion
missing-tensor synthesis
checkpoint repair
LM-head materialization
weight tying by payload overwrite
```

The gate should open files without write authority where the platform permits.

Required counters:

```text
checkpoint_write_count = 0
index_write_count      = 0
shard_write_count      = 0
payload_mutation_count = 0
```

# 19. Gate execution order

The physical gate must execute in this order:

```text
1. Resolve RepoRoot and output paths.
2. Import and verify R5-R5 parent manifest.
3. Read and hash production config bytes.
4. Parse and validate complete production ModelSpec.
5. Verify config convergence with R5-R3/R5-R5 authorities.
6. Resolve exactly one checkpoint root mode.
7. Read and hash index bytes when indexed mode is selected.
8. Derive the exact referenced shard path set.
9. Stream-hash every shard and verify expected CAS identities.
10. Parse every Safetensors header.
11. Verify weight_map-to-header ownership.
12. Construct the physical tensor inventory.
13. Derive the canonical architecture schema.
14. Resolve every physical key to a canonical role.
15. Verify all required roles and all layer indices.
16. Verify dtype, shape, element count and byte range.
17. Verify tied-role representation.
18. Verify zero synthetic tensors and zero payload mutation.
19. Execute the negative-control suite.
20. Seal CheckpointTensorSetAuthority.
21. Write detached receipts and local manifest.
22. Emit the PASS token.
```

The authority must not be sealed before the negative-control suite passes.
