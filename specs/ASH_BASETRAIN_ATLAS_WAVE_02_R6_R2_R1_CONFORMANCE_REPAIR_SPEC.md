# 15. Candidate route semantics

Candidate inputs:

```text
Q: exact R6 NeoX BQHD raw lease
K: chunk-local rgba32float D2Array texture
mask: full-valid causal authority
positions: exact R6 position authority
```

For every query row, query head and KV block:

```text
query_token = q_token_base + query_row
query_absolute = position_ids[selected_batch, query_token]
local_token = kv_block * 16 + lane_column
global_token = chunk_token_start + local_token
key_absolute = position_ids[selected_batch, global_token]

admitted =
    lane belongs to active 16-column half
    && query_token < row_valid_length
    && local_token < chunk_token_count
    && global_token < source_seq_len
    && key_absolute <= query_absolute
```

For admitted keys:

```text
score = dot(Q, K) * (1 / sqrt(64))
```

Subgroup reduction produces:

```text
max
exp_sum = sum(exp(score - max))
admitted_count
flags
```

For no admitted key:

```text
max_bits       = 0xff800000
exp_sum_bits   = bitcast(0.0)
admitted_count = 0
flags          = FINAL_WRITE without VALID
```

Each record must increment a dedicated write-count word exactly once.

# 17. Independent causal invariant

Candidate-oracle parity is necessary but not sufficient because both routes can share the same causal bug.

R6-R2-R1 adds a second verifier derived from position authority rather than score parity.

For the admitted full-valid contiguous profile:

```text
expected admitted count for query q and chunk c
  = count of key positions in chunk c where key_position <= query_position
```

For seq 32 and chunks [0..15], [16..31]:

```text
query position 0:
  chunk 0 admitted total 1
  chunk 1 admitted total 0

query position 15:
  chunk 0 admitted total 16
  chunk 1 admitted total 0

query position 16:
  chunk 0 admitted total 16
  chunk 1 admitted total 1

query position 31:
  chunk 0 admitted total 16
  chunk 1 admitted total 16
```

The invariant verifier must compare each record's `admitted_count` against an independently derived expected value.

Required counter:

```text
causal_admitted_count_mismatch_count == 0
```

A parity-clean but causal-invalid run must FAIL.

Use bit-level finite classification compatible with the project shader dialect:

```text
exponent_bits = bits & 0x7f800000
```

```text
exp_sum must be greater than 0 when admitted_count > 0
```

# 29. Gate sequence

Canonical physical gate order:

```text
1. parse CLI and expand environment variables
2. import R6, R5-R7, R5-R6 and required ancestor manifests
3. verify canonical PASS tokens and authority continuity
4. execute R6 parent path once in the same process
5. obtain actual R6 Q/K/V and context live leases
6. compare same-process R6 results against imported R6 manifest
7. seal complete R6-R2-R1 invocation identity
8. verify admitted batch, row-valid and position profile
9. verify BQHD and BHQD shapes, byte lengths and lease identities
10. build canonical multi-chunk plan
11. allocate bounded texture slots by chunk size
12. for each chunk in canonical order:
    a. acquire slot
    b. gather K/V BQHD into chunk-local textures
    c. for each query tile:
       i. allocate 16-byte candidate records and write counts
       ii. allocate 16-byte oracle records and write counts
       iii. encode candidate Stage10
       iv. encode raw oracle Stage10
       v. encode 64-byte parity verifier
       vi. encode causal invariant verifier
       vii. submit on the same R6 queue
       viii. observe completion
       ix. read exactly 64-byte compact status
       x. validate full record coverage and all counters
       xi. retain candidate/oracle statistics handles
    d. retain V texture handle
    e. retire or recycle slot only after completion ownership permits
13. seal KV texture wave authority
14. seal Stage10 shadow authority from observed counters
15. build retained live handoff from actual handles
16. seal retained handoff receipt from live handoff
17. verify R6 Headwise writer and context backing identity unchanged
18. verify all forbidden counters zero
19. execute fault-injection matrix in isolated negative cases
20. write canonical receipts and local manifest
21. print PASS token only after all positive and negative evidence passes
```
