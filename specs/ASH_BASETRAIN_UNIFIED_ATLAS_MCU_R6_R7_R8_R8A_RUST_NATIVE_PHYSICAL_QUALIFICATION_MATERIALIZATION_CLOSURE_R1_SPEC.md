# ASH-BASETRAIN-UNIFIED-ATLAS-MCU-R6-R7-R8-R8A-RUST-NATIVE-PHYSICAL-QUALIFICATION-MATERIALIZATION-CLOSURE-R1

## Purpose

Materialize the currently missing R6, R7, R8, and R8A production qualification receipts from real Rust-native GPU execution. Receipts are consequences of physical execution, not handwritten admission inputs.

## Authority

- Build/binary authority: Native CF1 sealed `base_train.exe`.
- Parent compatibility: current Cross-Release Physical Parent authority.
- Device truth: existing `ExistingDeviceBootstrap` and its live `wgpu::Device/Queue`.
- Physical executor: existing `TensorCubeLocalMuonBatchExecutor`.
- Qualification mode: child-only mode inside the existing `base_train` binary.
- No new `ash_core` authority, control-runtime authority, GPU runner binary, Device, Queue, Python validator, or PowerShell gate.

## Entry

The existing `base_train` binary gains:

- `--materialize-unified-atlas-mcu-physical-qualification-r1`
- `--mcu-physical-qualification-output-root <path>`
- `--mcu-r8-policy-source <path>`
- optional `--mcu-physical-qualification-require-e2`

The existing `--native-cf1-release-authority` and `--n8-cross-release-parent-compatibility-authority` are mandatory in qualification mode.

## Physical chain

1. Validate current executable against Native CF1.
2. Validate Cross-Release receipt and bind its consumer CF1/binary identity to the current executable.
3. Acquire one existing Device/Queue and require the physical subgroup probe to report exact 32.
4. Materialize a bounded deterministic four-job 16x16 fixture.
5. Execute E0 F32 baseline physically.
6. Emit R6 v1 qualification receipt only after physical fixture coverage succeeds.
7. Execute E1 physically and compare all candidate-weight, momentum, and orthogonal-update values against E0 under the versioned R7 E1 bound.
8. Attempt E2 in the same way. E2 may be absent unless explicitly required.
9. Derive the live qualified-expert mask and expert-manifest digest from the physically generated R7 receipts.
10. Load an explicit R8 policy source, verify its source digest, evaluate the same bounded descriptor fixture twice, require identical assignment manifests, and require at least two nonempty selected experts. The harness never modifies costs to force heterogeneity.
11. Execute the R8 assignment through the existing R8A indexed pipelines with one packed u32 descriptor-index view.
12. Require the existing Queue submission witness and exact submission wait from the backend.
13. Execute direct baselines for the exact expert selected for each job and require exact tile/status parity with the indexed R8A result. R7 owns mixed-precision tolerance; R8A owns index-indirection parity.
14. Emit existing-loader-compatible R6/R7/R8/R8A v1 receipts.
15. Seal a top-level qualification bundle and atomically rename staging to the final output root.

## Fixture

The semantic fixture ABI is `ASH.MCU.PHYSICAL.QUALIFICATION.FIXTURE.R1`.

The current fixture is bounded to four 16x16 TensorCube jobs. Numerical payload is deterministic and generated by Rust constants/ordinal formulas. R8 valid-element geometry varies across the four descriptors to exercise the declared R8 feature surface without inventing undeclared tensor statistics.

## R6 receipt

Schema remains `ash.basetrain.mcu.tensorcube_job_queue_r6.qualification.v1`.

The materializer emits the existing exact schema/digest after the bounded physical E0 fixture demonstrates complete job coverage and no output/descriptor divergence. No v2 production loader is created.

## R7 receipts

Schema remains `ash.basetrain.mcu.execution_expert_r7.qualification.v1`.

E1 and E2 receipts are independent. E0 is the reference expert and does not require a separate qualification file. E1/E2 are emitted only after real pipeline execution on the current Device. The numerical bounds are versioned Rust constants owned by the R7 qualification contract, not runtime-adjusted empirical slack.

Minimum heterogeneous expert set is E0+E1. If E2 fails and `--mcu-physical-qualification-require-e2` is absent, no E2 PASS-shaped receipt is written.

## R8 receipt

Schema remains `ash.basetrain.mcu.router_policy_qualification_r8.v1`.

The policy source is explicit. It must self-digest correctly. The exact same descriptors and qualified expert mask are routed twice and must produce the same assignment digest. At least two expert buckets must be selected. No policy mutation or stochastic routing is introduced.

## R8A receipt

Schema remains `ash.basetrain.mcu.gpu_resident_expert_bucket_r8a.qualification.v1`.

The physical indexed execution must:

- contain at least two nonempty expert buckets;
- use only packed u32 descriptor indices as partition control data;
- observe the existing Queue submission and exact wait;
- preserve zero source/momentum/candidate repack bytes and zero additional bucket D2H;
- exactly match the corresponding direct selected-expert baseline per tile/status;
- preserve the existing 65,536-byte maximum index-payload bound.

## State mutation exclusion

Qualification mode performs no training generation advance, optimizer commit, checkpoint commit, Physical N2 write, replay, rematerialization, or parent mutation. The bundle records zero counts for those mutation classes.

## Publication

Receipts are first written under `<output-root>.staging`. The final root is published only after all required receipts and the top-level bundle are sealed. A failed run must not leave a final production-adoptable bundle.

Recommended final layout:

```text
<output-root>/
  qualification_bundle_manifest.json
  r6/r6_qualification_receipt.json
  r7/r7_e1_qualification_receipt.json
  r7/r7_e2_qualification_receipt.json   # only if qualified
  r8/r8_qualification_receipt.json
  r8a/r8a_qualification_receipt.json
```

## PASS

`PASS_ASH_BASETRAIN_UNIFIED_ATLAS_MCU_R6_R7_R8_R8A_RUST_NATIVE_PHYSICAL_QUALIFICATION_MATERIALIZATION_CLOSURE_R1`

means the current CF1-sealed binary on the current physical Device actually executed and sealed the complete R6 -> R7 -> R8 -> R8A qualification chain. It does not mean a production training Wave has passed Phase 3, and it does not claim performance improvement, ActiveAsync qualification, or retry/escalation qualification.
